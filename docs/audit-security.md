# Security Audit Report — Uzmoon Forge V0.9

> Audit date: September 2026  
> Scope: Full codebase as of commit `4c46a0d` + V0.9 addendum  
> Method: Manual static analysis of all source files; no automated scanner used  
> Auditor: Internal — architecture review by primary author

---

## Summary

| Area | Status | Notes |
|---|---|---|
| Secret storage | PASS | Secrets in OS keychain via `secret-store`; never in DB |
| IPC surface | PASS | contextBridge allowlist; no `nodeIntegration` |
| Snapshot path traversal | PASS | Paths validated against `snapshotsDir` prefix |
| Project file access | PASS | Eligibility engine gates all project reads |
| Incident sanitization | PASS | Secrets + absolute paths redacted before persistence |
| Sharing opt-in | PASS | `incidentSharingEnabled: false` by default |

Overall security posture: **ACCEPTABLE** for a local-only desktop app.  
No external network surface beyond user-configured agent endpoint.

## 1. Secret Storage

**Finding:** API keys are stored via `SecretStore` (OS keychain on macOS, credential
store on Windows). They are never written to `forge.json` or any incident record.

**Evidence:**
- `src/main/secret-store/secrets.ts` — uses OS-level storage
- `src/main/reliability/sanitizer.ts` — `redactSecrets()` applied before any log/incident
- `detectResidualSecrets()` assertion available in all reliability tests

**Risk:** None identified.

---

## 2. IPC Attack Surface

**Finding:** The renderer process cannot call arbitrary Node.js APIs. All IPC is
mediated through `contextBridge.exposeInMainWorld("forgeApi", ...)` in
`src/preload/index.ts`. The main process validates arguments before acting on them.

**Evidence:**
- `src/preload/index.ts` — only approved channels exposed
- `webPreferences.contextIsolation = true` (Electron default in v12+)
- `webPreferences.nodeIntegration = false` (Electron default)

**Risk:** Low. The threat model is local-only; the renderer cannot reach the network
or filesystem except through the approved IPC channels.

**Note:** IPC handlers do not authenticate the renderer — all IPC is trusted as
coming from the same app process. This is appropriate for a local desktop app with
no multi-user model.

---

## 3. Filesystem Path Traversal

**Finding:** All snapshot reads validate that the resolved path begins with `snapshotsDir`
before reading. Project file reads are gated through `eligibility.ts`.

**Evidence:**
- `src/main/queue/QueueManager.ts` — `deleteOrphanedSnapshots()` includes guard:
  `if (!resolvedPath.startsWith(snapshotsDir)) continue;`
- `src/main/project-files/eligibility.ts` — all file eligibility checks here; renderer
  never calls these directly
- `src/main/project-files/edit-ir.ts` — `MAX_CONTEXT_BYTES = 512KB` per-file cap

**Risk:** Low. Path construction uses `path.join(snapshotsDir, id + ".txt")` — the `id`
is a UUID generated by `randomUUID()`, so traversal via crafted IDs is structurally impossible.

---

## 4. Edit Apply Safety

**Finding:** The file editing pipeline enforces a multi-step gate before any byte
is written to user project files.

Gate steps:
1. `status === "ready"` check (requires prior `verifyBaseSnapshot` success)
2. Apply lock (`Map<string, true>` keyed by `projectId:relativePath`)
3. Preflight check (`preflightFileEdits`) — verifies file unchanged since snapshot
4. Backup creation before first write
5. Rollback on any write failure

**Evidence:** `src/main/ipc/handlers.ts` — `EDIT_IPC.APPLY_SELECTED` handler;
`src/main/project-files/edit-service.ts` — `restoreFromBackup()` with 6 arguments
including `appliedContentHash`.

**Risk:** Low. The `APPLY_REQUIRES_APPROVAL` invariant is monitored at runtime;
violations are recorded as incidents.

---

## 5. Incident Data Privacy

**Finding:** All `observedState` objects are passed through `sanitizeState()` before
the incident is stored. The sanitizer applies `redactSecrets()` + `redactAbsolutePaths()`
recursively through nested objects.

**Evidence:**
- `src/main/reliability/incident.ts` — `record()` method calls `sanitizeState(violation.observedState)`
- `src/main/reliability/sanitizer.ts` — `SENSITIVE_KEYS` set for nested object key redaction
- Test assertion: `detectResidualSecrets(JSON.stringify(sanitized)).toHaveLength(0)`

**Finding:** The `getSharePayload` IPC handler returns `null` when
`incidentSharingEnabled === false` (default). No sharing can happen without the user
explicitly enabling it in Settings → Privacy.

**Risk:** None identified.

---

## 6. Agent Endpoint Trust

**Finding:** The agent endpoint is user-configured. The app sends chat messages to
this endpoint and receives streamed text. The received text is:

1. Parsed for `forge_tool` / `forge_final` / `forge_structured_edit_proposal` fences
2. Never `eval()`-ed or executed as code
3. Never injected into OS commands

**Finding:** The `normalizeDecision()` function enforces that the model cannot
instruct Forge to skip invariant checks, disable sanitization, or apply code changes.
The model output channel is strictly limited to:
- Tool calls (structured; executed by `tool-executor.ts` with fixed argument types)
- `forge_final` text (displayed to user)
- `forge_structured_edit_proposal` (requires explicit user approval)

**Risk:** Low. The model cannot escalate privileges or bypass the approval boundary
through crafted responses.

---

## 7. Protocol Injection

**Finding:** User message content and file context are injected into the provider
request body as structured JSON. No shell-style interpolation is used.

**Evidence:**
- `src/main/agent-client/client.ts` — `buildAnthropicBody()` / `buildOpenAIBody()` construct
  the payload as typed objects, not string concatenation
- `src/main/queue/QueueManager.ts` — `buildContextXml()` escapes file content in a
  `<file_content>` block; no unescaped interpolation

**Risk:** None identified for local use. (Standard XML injection caveats apply if
the file content itself contains `</file_content>` — the current implementation does
not escape this; a future hardening pass should add CDATA wrapping.)

**Recommendation (low priority):** Wrap `<file_content>` blocks in `<![CDATA[ ... ]]>`
to prevent any `</file_content>` in user files from closing the block early.

---

## 8. Self-Healing Boundary

**Finding:** `SelfHealingEngine` has no `autoApply()` method. `approveCandidate()`
returns `boolean` and has no side effects beyond setting `approvalState`. No code path
reads a candidate and writes source files.

**Evidence:** `src/main/reliability/self-healing.ts` — audited in full;
`improvement-candidate.test.ts` — ic-4 tests confirm structural absence of auto-apply.

**Risk:** None identified.
